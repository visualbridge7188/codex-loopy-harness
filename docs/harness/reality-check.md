# 하네스 현실 점검 — 실용적 가이드

> **핵심 인정**: 현재 하네스는 "마크다운 문서 프레임워크"입니다.
> 스킬, 에이전트, 커맨드는 모두 **AI가 읽고 따르는 지시서**이지, 실행 가능한 코드가 아닙니다.

---

## 1. 현재 상태 정리

### 실행 가능한 것 (실제 작동)

| 항목 | 파일 | 상태 |
|------|------|------|
| Hooks (10개) | `hooks/*.sh` | ✅ 쉘 스크립트 — Claude Code에서 자동 실행 |
| AGENTS.md | 루트 | ✅ Claude Code가 자동 로드 |
| CLAUDE.md | 루트 | ✅ Claude Code가 자동 로드 |
| settings.json | 루트 | ✅ Claude Code 설정 |

### "지시서"인 것 (AI가 읽고 수동 수행)

| 항목 | 파일 | 상태 |
|------|------|------|
| Agents (15개) | `agents/*.md` | 📄 페르소나 정의 — AI가 역할扮演 |
| Skills (8개) | `skills/*/SKILL.md` | 📄 단계별 지시서 — AI가 순서대로 수행 |
| Commands (6개) | `commands/*.md` | 📄 워크플로우 설명서 |

---

## 2. 그럼 어떻게 쓰는 건가?

### Claude Code에서의 사용법

Claude Code는 `CLAUDE.md`와 `AGENTS.md`를 **자동으로 로드**합니다.
따라서:

```
1. Claude Code 실행
2. CLAUDE.md가 자동 로드됨 → 하네스 규칙 활성화
3. Hooks가 자동 트리거됨 → 파일 변경 시 검증 실행
4. 사용자가 명령 입력 → AI가 commands/*.md를 참조하여 수행
```

**핵심**: Claude Code에서는 "설치" 개념이 필요 없습니다.
파일이 워크스페이스에 있으면 자동으로 인식됩니다.

### Cline (현재 환경)에서의 사용법

Cline은 `CLAUDE.md`를 인식하지만, `commands/`나 `skills/`를 자동 로드하지 않습니다.

```
1. /team 하고 싶으면 → commands/team.md 내용을 복사해서 입력
2. /qa-cycle 하고 싶으면 → skills/qa-cycle/SKILL.md 내용을 복사해서 입력
3. 에이전트 역할 부여 → agents/xxx.md 내용을 컨텍스트로 제공
```

## 3. 추천 워크플로우가 의미가 있는가?

### 의미 있는 부분 ✅

| 요소 | 이유 |
|------|------|
| **3-레이어 아키텍처** | 역할 분리 원칙은 프롬프트 엔지니어링에 유효 |
| **Fail-Closed 규칙** | 검증 게이트 개념은 코드 품질에 실제 도움 |
| **Hooks (10개)** | 유일한 실행 가능 코드 — 실제 자동화 |
| **파일 경계 규칙** | 에이전트가 수정할 파일 범위 제한은 의미 있음 |

### 의미 없는 부분 ❌

| 요소 | 이유 |
|------|------|
| **8-Phase SDLC 자동화** | 자동화 인프라 없음 — AI가 수동으로 따라야 함 |
| **15개 에이전트 동시 운용** | 단일 AI가 페르소나 전환만 가능, 실제 병렬 아님 |
| **QA Cycle 자동 루프** | 루프 로직 없음 — AI가 판단해서 반복해야 함 |
| **Self-improve** | 메타 시스템 인프라 없음 |

## 4. 실용적 추천 — 무엇을 버리고 무엇을 남길까

### 남기는 것 (실제 가치)

```
✅ AGENTS.md         — 핵심 규칙 (간결하게 유지)
✅ CLAUDE.md         — 프로젝트 컨텍스트
✅ hooks/            — 실제 실행 가능한 자동화
✅ rules/            — 코딩 규칙 (AI가 참조)
✅ docs/harness/     — 참고 문서
```

### 축소/통합 대상

```
🔄 agents/ (15개 → 5개 핵심만)
   → manager, frontend, backend, qa, devops
   → 나머지는 필요시 manager가 역할 위임

🔄 skills/ (8개 → 3개 핵심만)
   → init-project, team(8-phase), qa-cycle
   → 나머지는 team 스킬 내부 단계로 통합

🔄 commands/ (6개 → 2개)
   → /team (모든 개발 워크플로우)
   → /init (프로젝트 초기화)
```

### 버리는 것

```
❌ loopy-era-eval    — 평가 인프라 없음
❌ harness-report    — 리포트 생성 불필요
❌ discover-skills   — 외부 스킬 검색 불필요
❌ self-improve      — 메타 시스템 미구현
```

## 5. 실제 워크플로우 시작 방법

### Claude Code 환경 (권장)

```bash
# 1. 저장소 클론
git clone https://github.com/visualbridge7188/codex-loopy-harness.git my-project
cd my-project

# 2. Claude Code 실행
claude

# 3. CLAUDE.md가 자동 로드됨 → 바로 작업 시작
> /team  # 8-Phase SDLC 시작
```

### Cline 환경 (현재)

```
1. 워크스페이스 열기 (이미 열려있음)
2. commands/team.md 내용을 프롬프트로 입력
3. AI가 단계별로 수행
```

## 6. 결론

**하네스는 "프롬프트 엔지니어링 프레임워크"로서 가치가 있습니다.**
실제 자동화 시스템이 아니지만, 구조화된 지시서를 통해 AI의 출력 품질을 높이는 역할을 합니다.

| 질문 | 답변 |
|------|------|
| 스킬 설치가 필요한가? | **아니요** — 파일이 있으면 AI가 읽습니다 |
| 에이전트가 실제 작동하는가? | **페르소나 전환**으로 부분 작동 |
| 추천 워크플로우가 의미 있는가? | **구조적 가이드로서는 의미 있음, 자동화로서는 아님** |
| 무엇을 먼저 해야 하나? | **핵심만 남기고 축소 → 실제 프로젝트에 적용** |
