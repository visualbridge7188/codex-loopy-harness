# Notes DB Notebook Candidates

* **작성일**: 2026-06-09
* **상태**: 자동 분류 후보 분석
* **대상**: Notion Notes DB

---

## 1. 목적

Notes DB의 제목, 설명, genre, tag, Topic을 기준으로 Notebook 자동 묶기 후보를 만든다.

## 3. 품질 진단

초기 규칙 기반 분류는 그대로 대량 적용하기에 위험하다.

문제:

1. `워드프레스/웹사이트 제작` 후보가 너무 넓다.
2. `플러그인`, `사이트`, `SEO`, `랜딩` 같은 단어가 AI/마케팅 자료까지 흡수한다.
3. `독서/강의/성장` 후보도 `강의` 단어 때문에 AI 강의, 정부지원사업 강의, 개발 강의가 섞인다.
4. `부동산/내집마련` 후보는 Topic이 `투자/부동산`인 자료를 많이 포함하지만, 실제로는 투자/코인/자산 자료까지 섞인다.
5. `재무/투자` 후보도 `돈`, `수익`, `자산` 같은 넓은 단어 때문에 비즈니스/마케팅 자료가 섞인다.

따라서 이 후보를 즉시 적용하지 않는다.

---

## 4. 실행 가능한 방향

Notebook 자동 묶기는 넓은 규칙보다 고신뢰 규칙부터 적용한다.

추천 우선순위:

1. 이미 완료한 `헤르메스 Life OS`
2. `AI 에이전트`
3. `노션/생산성 시스템`
4. `블로그/SNS 콘텐츠`
5. `교육/학교/교사`
6. `부동산/내집마련`
7. `워드프레스/웹사이트 제작`
8. `마케팅/브랜딩/세일즈`
9. `재무/투자`

---

## 5. 운영 원칙

1. Notebook은 모든 Note에 강제하지 않는다.
2. Topic은 기본 분류로 유지한다.
3. Notebook은 자료가 충분히 쌓인 소주제 컬렉션에만 쓴다.
4. 자동 분류는 먼저 고신뢰 후보만 적용한다.
5. 넓은 키워드 기반 대량 분류는 오분류가 많으므로 금지한다.

---

## 6. 기술적 제약

로컬 Notion API 통합은 Notes DB와 Project DB는 조회/수정할 수 있지만, Notebook DB를 직접 조회하지 못했다.

확인된 제약:

1. Notebook DB API query는 404를 반환했다.
2. Notion MCP는 Notebook DB fetch/create/update가 가능했다.
3. 따라서 대량 Notebook relation 업데이트를 API로 하려면 Notebook DB와 새 Notebook 페이지가 해당 integration에 공유되어야 한다.

대안:

1. 사용자가 Notebook DB를 `AI Agent` integration에 공유한다.
2. 그러면 API로 대량 Notebook relation 업데이트가 가능하다.
3. 공유하지 않으면 MCP로 소량 배치만 처리한다.
